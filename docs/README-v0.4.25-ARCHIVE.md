# 글클메 번역애드온 v0.4.25

v0.4.24 기반 통합 패치입니다. 기존 UI·OBS·아이템 사전·한국어→영어 입력 번역을 유지합니다. 이전 버전 폴더 없이 빌드할 수 있는 독립 ZIP이며, Windows에서 미리 생성한 EXE가 들어 있는 패키지는 아닙니다.

## 사용 방법

1. 실행 중인 이전 번역 프로그램을 종료합니다.
2. ZIP 전체를 새 폴더에 풉니다.
3. `BUILD-WINDOWS.bat`를 실행합니다.
4. 성공 후 `dist\글클메 번역애드온\글클메 번역애드온.exe`를 실행합니다.
5. 하단 채팅의 닉네임·본문을 모두 포함해 인식 영역을 지정합니다. 과거 로그 판정도 사용하려면 오른쪽 게임 채팅 스크롤바까지 포함하세요.

최초 빌드에는 Python 패키지·영↔한 모델 다운로드를 위한 인터넷 연결이 필요합니다. OCR 모델 3개는 ZIP에 포함했습니다. 실행 중 번역 API를 사용하지 않습니다. ONNX 진단 전송은 프로세스 초기화 전부터 비활성화합니다.

기존 사용자 설정·직접 등록한 아이템 사전·기존 ID 대응 데이터는 이어서 사용합니다. 아이템 DB 전체 사용법과 기존 기능은 `docs/README-v0.4.24-ARCHIVE.md`를 참고하세요.

## 빌드 실패 수정

첨부 BUILD-REPORT의 실제 실패 원인은 CP949 출력 중 `–` 문자를 인코딩하지 못한 UnicodeEncodeError였습니다. OCR 판독 자체가 실패한 로그는 아니었습니다.

- PowerShell의 Python 실행을 `-X utf8 -u`와 UTF-8 출력 환경으로 통일했습니다.
- 직접 실행하는 OCR/모델 검사 스크립트도 stdout/stderr를 UTF-8로 설정합니다.
- CP949 환경을 강제로 지정한 자식 프로세스 검사와 실제 캡처 재생을 통과했습니다.
- 실제 Python 오류가 발생하면 빌드는 계속 실패 처리합니다. 검사 단계를 삭제하거나 오류 코드를 무시한 수정은 아닙니다.

## 번역

- 아이템 링크·가격을 제외한 거래 문장 틀을 캐시합니다. `[Kitty Chat Ring] S>Pm Offers`와 `[다른 아이템] S>Pm Offers`는 동일한 틀을 재사용하면서 각 아이템을 보존합니다.
- 검증된 사전 이름을 우선하고, 대괄호 안의 미확인 이름은 그대로 유지합니다. 금액은 Decimal 코드로 변환합니다.
- 일반 모델을 사용하는 복잡한 문장은 링크 아이템·가격을 슬롯으로 보호합니다. 슬롯이 삭제·복제되거나 숫자가 달라지면 채택하지 않습니다. 폴백도 실제 아이템/가격을 문장 모델에 다시 맡기지 않고 주변 절만 번역합니다.
- 일반적인 레벨·수량 문장은 문맥을 유지해 번역한 뒤 숫자열이 원문과 정확히 일치하는지 검증합니다. 불일치하면 슬롯 보호 경로로 복구합니다.
- S)/5> 교정은 문장 맨 앞이고 아이템 링크·가격 같은 독립적인 거래 증거가 있을 때만 적용합니다. 닉네임과 링크 안의 이름은 인사/대문자/늘인 글자 정규화 대상에서 제외합니다.
- 안전한 구분자에 따라 절을 나눕니다. S>, a/w, c/o, URL, 아이템 링크, 1/2 같은 분수는 무작정 쪼개지 않습니다.
- LFM, KPQ, CC, BRB, OBO, IDK, RN, U/UR의 확실한 문맥 등을 먼저 처리합니다. 짧은 기호 조각은 모델 환각 대신 원문을 유지합니다.

## 번역 엔진과 지연 방지

- Argos 배포 영↔한 전용 모델 + CTranslate2를 유지합니다. 모델 교체나 로컬 LLM 도입은 하지 않았습니다.
- CPU 지원 타입을 먼저 확인해 INT8 계열을 선택하고 실제 타입을 기록합니다. 모델 경로/모델 손상 오류를 조용한 FP32 재시도로 덮지 않습니다.
- `inter_threads=1`, `intra_threads=2`, `beam_size=2`, 최대 8문장 배치입니다.
- 출력 길이는 입력 토큰 수에 맞춰 `min(180, max(24, max_src*3+10))`으로 제한하고 `no_repeat_ngram_size=3`을 적용합니다.
- `replace_unknowns=False`와 종료 토큰 반환을 사용합니다. 상한까지 생성했는데 종료되지 않은 출력이나 `<unk>`가 남은 결과는 그대로 표시하지 않습니다.
- 시작 시 양방향 번역·OCR을 워밍업합니다. 워밍업이 끝난 후 화면 감시를 시작합니다.

## OCR

- 글줄 분리 → 배경 제거 → 모델 입력 높이로 확대 → 변경된 줄만 인식합니다. 기본 다국어 모델은 명시적 CUBIC 확대를 사용합니다.
- 줄 높이를 학습해 두 줄이 붙은 덩어리를 검출합니다. 약한 대비를 위해 문턱값을 화면 전체에서 낮추지 않고, 기존 강한 글줄과 떨어진 약한 문자 성분만 보완합니다.
- 기본 PP-OCRv6 small + 한국어 PP-OCRv5 보완을 유지합니다. 32/48 높이와 한국어 모델 단일화는 비교했고, 충분한 품질 개선 근거가 없는 변경을 기본값으로 강행하지 않았습니다.
- 캡처에서 교정한 CH 아이콘 템플릿이 확실히 맞고 닉네임·콜론이 확인되면 이름과 본문을 나눠 읽습니다. 이름 영역은 본문과 독립적으로 전처리·캐시합니다. 아이콘 크기/모양이 다르거나 접두부가 잘렸으면 전체 줄 OCR로 돌아갑니다.
- 배경색은 OCR 전에 측정합니다. 빨간색만 보고 공지라고 버리지는 않습니다. 사용자가 요청한 시스템 획득 공지 제외와 빨간 유저 확성기 유지는 그대로입니다.
- 해시는 전처리한 이미지의 완전 일치입니다. 근사 해시로 숫자가 바뀐 줄을 재사용하지 않습니다. 메시지 신규 여부는 별도의 이전/현재 프레임 순서 정합으로 판단합니다.

## 스크롤과 표시

- 게임의 파란 스크롤 레일/손잡이를 확인할 수 있고 맨 아래가 아니면 신규 번역을 대기합니다. 맨 아래로 돌아오면 과거 로그를 새 채팅처럼 재등록하지 않습니다.
- 스크롤바가 잘렸거나 다른 UI 형식이면 상태를 `unknown`으로 표시합니다. 보이지 않는 스크롤 위치를 추측하지 않습니다.
- 일반채팅 연속 화면 확인, CH05를 닉네임으로 오인하는 현상 차단, 동일 문장을 말한 여러 사람의 메시지 보존, 수집 순서대로 표시하는 기존 패치를 유지합니다.

## 진단과 CPU

OCR 진단 상세에서 다음을 볼 수 있습니다.

- 줄 분리, 사전 색상 분류, 1차 인식, 원본색 재시도, 한국어 보완, 검출 복구의 시간
- 최근 256회 범위의 중앙값·p95·최대값, 실행 중 누적 최대값과 호출 수
- 실제 인식이 발생한 OCR 시간과 캐시를 포함한 전체 프레임 처리 시간의 구분
- 재시도/한국어 보완 발동 비율, 접두부 캐시 적중, 거래 틀 적중
- 캡처→번역 신호까지 / 캡처→UI 슬롯 반영까지의 시간, 번역 대기열, 과부하 횟수
- 프로세스 CPU 사용률. `core_pct` 100은 코어 한 개 분량이며 `machine_pct`는 논리 코어 수로 정규화한 값입니다.

UI 슬롯 시간은 실제 모니터 페인트 완료나 OBS의 다음 폴링까지 측정한 값은 아닙니다.

설정 → 채팅 디자인 → `게임 우선 · 번역 프로그램 CPU 우선순위 낮추기`를 켜면 Windows에서 이 프로그램만 Below Normal 우선순위로 둡니다. 기본값은 끔입니다. 이 옵션을 켜면 게임을 우선하는 대신 번역 대기가 늘어날 수 있습니다.

## 검증과 한계

`VALIDATION-v0.4.25.md`, `PERFORMANCE-v0.4.25.json`, `TEST-RESULTS-v0.4.25.txt`에 실제 범위와 수치를 기록했습니다.

- 5줄 벤치마크는 합성 입력에서 모든 줄을 새로 OCR한 실험입니다. 실제 Windows 게임·FPS 검사가 아닙니다.
- 이 환경에서 Windows EXE 생성 및 실게임 연속 플레이는 검증하지 않았습니다. 기존 빌더의 Windows 5.1 BOM·경로·출력 설정과 실제 Python 모델 검사를 검증했습니다.
- 화면 밖으로 지나간 문장, 다른 창에 가린 문장, 닉네임이 인식 영역 밖에 있는 문장은 추측해서 복원하지 않습니다.
- 동일한 글이 화면의 모든 줄을 채운 상태에서 새 도배가 와도 픽셀이 전혀 바뀌지 않는다면, 화면 캡처만으로 새 이벤트 발생을 알아낼 수 없습니다.
- GPU 전환, 글자 템플릿 사전 전체 구축, 모델 파인튜닝은 게임 PC/폰트/정답 자료 없이 강행하지 않았습니다. CPU 경로와 전체 줄 복구 경로를 유지했습니다.
